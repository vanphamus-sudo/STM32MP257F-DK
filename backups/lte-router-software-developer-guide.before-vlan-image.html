The complete software stack

02 / Separate hardware enablement, control and packet forwarding

Control plane: UCI stores policy; netifd configures interfaces and routes; ModemManager sets up the modem; firewall4 produces nftables rules. The Python application coordinates these components.

Data plane: Linux moves ordinary client packets between interfaces using the installed routes and rules. Internet packets do not pass through the web server or ModemManager. Industrial proxies and VPN programs can process their own payload streams.

Hardware enablement: firmware, device trees and drivers make peripherals usable before router policy exists. Linux cannot compensate for an unpowered modem, missing SIM, wrong device tree or incompatible driver.

The Cortex-A35 application processors run Linux. A custom Cortex-M33 routing program is not required for this documented packet path. The cellular baseband runs its own firmware inside the Quectel module.

Follow one packet through the router

07 / DHCP, DNS, routing, NAT and the return path

Before the packet: dnsmasq leases the client an address, gateway and DNS options. DNS resolves a hostname. The client sends an Ethernet frame to the router’s MAC because the destination is outside its subnet.

Outbound: the Ethernet driver receives the frame. Linux identifies the IP destination, consults policy/routing tables, checks forwarding policy and connection state, then masquerades the source on the WAN egress. The USB WWAN driver delivers it to the modem.

Return: conntrack associates the response with the original flow; reverse NAT restores the LAN destination, routing selects the LAN and the driver transmits to the client.

Traffic typeKernel / userspace pathPractical distinction
Client to InternetForward path + NATAn outbound firewall forwarding rule is involved.
Client to web UI or SSHRouter input pathThis is router administration, not a port forward.
Router telemetry to brokerLocal output pathA client-forwarding data cutoff may still allow this.
Inbound to LAN serviceDNAT + forward pathRequires carrier reachability and explicit forwarding policy.
LAN to another LAN deviceMay remain in switch/bridgeRouted WAN policy may never see it.
OpenVPN payloadTunnel via userspace OpenVPN, then kernelCPU work and MTU differ from ordinary forwarding.
Carrier-grade NAT (CGNAT) is upstream of this device. DDNS, a local DMZ rule and passthrough cannot remove it. Use a reachable carrier service or an outbound VPN for remote access.

Local access & address services

08 / Basic client connectivity

Ethernet LAN, DHCP and DNS

Software: ethernet.py · netifd · dnsmasq · bridge · Ethernet driver

LAN clients receive private addresses and router/DNS options; Linux forwards permitted traffic to WAN.

Real-life uses
  • Connect a shop till and payment terminal to a local switch with LTE uplink.
  • Bring up a field laptop without manually assigning an IP address.
  • Resolve Internet hostnames for an industrial controller using the router’s DNS forwarder.

Conditions: Recorded LAN is 192.168.10.1/24. Avoid subnet overlap with upstream, VPN and USB networks.

DHCP MAC-to-IP reservations

Software: dhcp_reservations.py · dnsmasq UCI

Bind a device MAC to a predictable DHCP address.

Real-life uses
  • Keep a camera at a stable address for a forwarding rule.
  • Give a meter gateway a predictable target for remote support.
  • Replace manual static-IP spreadsheets for several small-site devices.

Conditions: Reservation is address management, not device authentication. Client must use DHCP; prevent duplicate assignments.

Wi-Fi hotspot

Software: wifi.py · wireless UCI · wpad/hostapd · brcmfmac

Provides an authenticated wireless AP on its own configured subnet.

Real-life uses
  • Give installers tablet access to the setup page.
  • Connect temporary site sensors where cabling is impractical.
  • Provide a small temporary office with LTE-backed wireless access.

Conditions: Recorded hotspot is STM32-LTE on 192.168.20.1/24. A separate subnet alone does not prove guest isolation; verify firewall policy.

Real-life uses

  • Provide a distinct network for a camera installation.

Conditions: Requires trunk mode and a managed switch. Does not create another Wi-Fi SSID. Verify actual isolation with cross-zone traffic tests.

Inbound reachability & handoff

10 / Give remote systems a path to local equipment

Port forwarding and NAT loopback

Software: port_forwarding.py · firewall4 · DNAT / conntrack

Map WAN or VPN-side ports/ranges to LAN services, with optional source restrictions and local hairpin access.

Real-life uses
  • Reach a camera recorder through a dedicated external port.
  • Expose a lab TCP test service to a trusted remote office.
  • Let local operators use the same reachable service name as remote users.

Conditions: Carrier inbound access is required. A source-restricted rule is preferable for sensitive services; test from outside the LAN.

WAN DMZ host

Software: port_forwarding.py · firewall4

Forward unmatched inbound IPv4 traffic to one selected LAN host; specific forwards retain priority.

Real-life uses
  • Place a downstream test firewall behind the LTE gateway.
  • Temporarily identify ports required by a vendor appliance.
  • Delegate inbound service handling to one dedicated edge server.

Conditions: It does not isolate the host or defeat CGNAT. Broad inbound exposure needs an appropriate downstream firewall.

DDNS and routed IP passthrough

Software: DDNS backend + ddns-scripts; ip_passthrough.py + supervisor

DDNS updates DynDNS/No-IP names. Passthrough exclusively routes the bearer IPv4 address to one Ethernet MAC using a /32 lease, without STM32 NAT.

Real-life uses
  • DDNS: keep a changing reachable LTE address behind a stable hostname.
  • Passthrough: let an existing enterprise firewall own site routing and NAT.
  • Passthrough: test a downstream router without a second STM32 NAT layer.

Conditions: Passthrough is not Ethernet bridging or modem-mode switching. Dedicated Ethernet LAN, connected IPv4 bearer and conflicting services disabled are required. End-to-end acceptance remains outstanding; CGNAT is unaffected.

Availability, accounting & performance

12 / Keep the site connected and control cost

LTE watchdog and WAN failover

Software: router_supervisor.py · bound probes · netifd · policy routing

Watchdog retries LTE then escalates recovery with cooldown. IPv4 failover probes Ethernet/LTE separately and requires stable recovery before returning.

Real-life uses
  • Recover a roadside device after a carrier session stalls.
  • Keep a shop operating when broadband loses upstream reachability.
  • Avoid rapid route flapping on an unstable wired link.

Conditions: Ethernet link-up alone is not Internet health. Existing sessions can reconnect after address/path changes. Probe targets must answer ICMP.

Persistent traffic and data allowance

Software: traffic_stats.py · router-traffic · feature accounting · nftables

Track cumulative traffic and estimated billing-cycle totals; warn or block client forwarding at the configured limit.

Real-life uses
  • Warn before a pooled SIM allowance is exhausted.
  • Compare a camera site’s daily consumption after a setting change.
  • Stop high-volume client uploads while retaining router-originated support traffic.

Conditions: Upload and download count; decimal MB; billing day 1–28 with UTC reset. Estimate differs from carrier billing. Slot-local allowance settings must match in both roots.

Smart Queue Management (SQM)

Software: sqm-scripts · CAKE kernel scheduler · ip/tc

Shape upload/download with CAKE to reduce queueing delay under load.

Real-life uses
  • Keep remote desktop usable during a bulk upload.
  • Protect interactive support while meters transfer daily CSV files.
  • Reduce latency spikes on a shared temporary office uplink.

Conditions: Set rates below sustainable capacity and retune for variable LTE. Required packages and matching scheduler module must exist; no throughput guarantee.

Serial gateway & modem command access

14 / Two services with deliberately different payloads

Transparent TCP-to-serial bridge

Software: serial_tcp.py · router-serial · PL2303 · sockets / termios

Forward binary bytes between one TCP client and the external converter; default TCP port 5000, 8N1, bounded buffering and idle expiry.

Real-life uses
  • Connect a legacy serial sensor to remote diagnostic software.
  • Operate a serial-only instrument from a central support PC.
  • Run an existing vendor serial protocol across an LTE link.

Conditions: Raw stream has no native encryption/authentication; use a protected path. Since r7 every byte, including AT$VERSION, reaches the external device. It is not the modem AT service.

Modem AT TCP and authenticated web console

Software: at_tcp.py · ModemManager serialized command API

Separate TCP port 11111 accepts modem commands. Reserved AT$VERSION is answered locally; unknown AT$ commands are rejected.

Real-life uses
  • Read modem signal diagnostics during support.
  • Confirm the router software identity without a browser.
  • Issue a vendor diagnostic command under controlled maintenance access.

Conditions: AT commands can disrupt LTE. Restrict reachability. Raw TCP access is separate from the authenticated web API; check current firewall exposure.

Exclusive serial assignment

Software: serial_assignment.py · procd · device ownership

Choose TCP bridge, Modbus collection or Disabled; stop the previous owner before starting the new owner.

Real-life uses
  • Switch a meter from automated polling to a vendor diagnostic session.
  • Keep an adapter reserved for maintenance while preserving saved settings.
  • Replace an adapter without relying on changing ttyUSB numbering.

Conditions: TCP bridge and Modbus cannot simultaneously own the converter. usb:067b:2303 selector rejects ambiguity; modem serial ports are separate.

Provide settings/status, guided examples and same-board allowlisted configuration export/import.

Network-change confirmation and rollback

Protected advanced network edits require confirmation within three minutes; otherwise restore previous files and reload services.

After Linux starts, short press reboots; hold eight seconds until orange LD9 is solid, then release to restore Ethernet/USB access and reboot.

  • Exit passthrough and regain ordinary LAN/NAT behavior.

Signed application .rupdate — build-update.pyReconstructed allowlisted, script-free application package; backup and health checks.Verified remote app release; backup reinstall is an attempted rollback, not power-fail-safe A/B.
Signed system .rupdate — build-system-update.pyMatching ext4 rootfs, kernel and board DTB written to inactive slot.OS/kernel upgrades with trial boot. Does not replace TF-A/FIP, partition table or bootloader.
Factory ZIP — build-factory.pyBlank-board image/programming bundle.Manufacturing/first installation. Offline-valid bundle still needs a blank-board boot test.

A delta is valid only with its exact verified base. The installer hashes reused/reconstructed content; missing or modified bases require a full bundle. A tiny reuse-only rehearsal is not evidence of typical update savings.

The signed release is the authority for new executable code. Store signing private keys off the router, provision only public trust material, and keep kernel, modules, DTB and rootfs coherent.

The repository contains separate historical Yocto/OpenSTLinux and current OpenWrt integration paths. Do not use the former module build or generic stock sysupgrade on the custom eMMC layout.
